## ليش ما منحفظ كل شيء بالـ RAM؟

الـ CPU بينفّذ تعليمات محمّلة بالذاكرة الرئيسية **Main Memory (ana bellek)**. الـ RAM سريعة نسبيًا، لكن حجمها محدود و**Volatile (uçucu)**: محتواها بينفقد عند انقطاع الكهرباء. لذلك منستخدم **Secondary Storage (ikincil depolama)** مثل HDD وSSD لحفظ البيانات بشكل **Nonvolatile (kalıcı / uçucu olmayan)**.

بالـ **Von Neumann Architecture (Von Neumann mimarisi)**، بتتخزن التعليمات والبيانات بالذاكرة، والمعالج بيجيب التعليمات (fetch)، بيفسّرها (decode)، وبينفّذها (execute). المعالج بيستخدم **Registers (yazmaçlar)** لتخزين قيم قريبة من التنفيذ.

## الهرمية

ترتيب تقريبي من الأسرع إلى الأبطأ: **Registers → Cache → Main Memory → SSD/HDD → Optical Disk / Magnetic Tape**. كل ما طلعنا لفوق غالبًا بتزيد السرعة والكلفة لكل bit وبتنقص السعة. ترتيب السرعات التفصيلي بيتغير حسب التقنية والجهاز.

**Caching (önbelleğe alma)** يعني نحط نسخة من بيانات بمستوى أسرع. لما المعالج أو البرنامج يطلب البيانات، بيفحص النسخة السريعة أولًا؛ إذا موجودة، بنوفر وصول أبطأ. وإذا مو موجودة، بنجيبها من المستوى الأدنى.

## I/O والـ DMA

الـ **I/O (giriş/çıkış)** هو نقل بيانات من وإلى الأجهزة. في أسلوب بيرجع فيه التحكم للبرنامج بعد اكتمال I/O، وأسلوب بيقدر يرجع فيه قبل اكتماله. الـ **System Call (sistem çağrısı)** واجهة بتسمح للبرنامج يطلب خدمة من الـ OS.

بالنقل التقليدي، مشاركة CPU بكل عملية نقل صغيرة ممكن تضيف **Overhead (ek yük)** كبير. **DMA — Direct Memory Access (doğrudan bellek erişimi)** بيسمح للـ Controller ينقل بلوك بيانات بين الجهاز والذاكرة بعد ما يجهّز النظام الـ Buffers والـ Pointers والعدادات. غالبًا بيُبلَّغ CPU باكتمال البلوك عن طريق Interrupt، وبيقدر يشتغل على مهام أخرى خلال النقل.

**مثال توضيحي خارج الشرائح:** نسخ ملف كبير من SSD إلى RAM بيستفيد من نقل كتل بدل ما يضطر المعالج يتعامل مع كل byte لحاله.
