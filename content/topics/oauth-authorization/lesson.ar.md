## تفويض محدود بدل مشاركة كلمة المرور

OAuth 2.0 بروتوكول تفويض (authorization)، مو بروتوكول إثبات هوية. الفكرة: تطبيق خارجي يحتاج يقرأ صورك، ما لازم تعطيه كلمة مرور حسابك كاملة. بتوافق عبر مزود الخدمة على صلاحية محدودة وقابلة للسحب، ويحصل التطبيق على access token. هاد الرمز مثل «مفتاح قدرة» (capability): اللي معه الرمز بيقدر ينفذ الصلاحيات المضمنة فيه، فحمايته مهمة مثل كلمة المرور.

الأدوار أربعة: مالك المورد (أنت)، العميل (التطبيق)، خادم التفويض (يطلب موافقتك ويصدر الرمز)، وخادم المورد (واجهة API التي تحمي البيانات). في تدفق authorization code، العميل يوجه المتصفح لمزود التفويض؛ المستخدم يصادق ويوافق؛ يرجع المتصفح برمز قصير العمر؛ العميل يستبدله من القناة الخلفية بـaccess token. تطبيقات العميل العامة ما بتقدر تحفظ client secret بشكل سري، لذلك PKCE بيربط طلب البداية بتبادل الرمز عبر verifier/challenge.

## النطاقات والتحقق من مسار العودة

النطاق (scope) لازم يكون أضيق صلاحية بتكفي للمهمة: `photos.read` بدل صلاحية تعديل وحذف كاملة. لازم عنوان redirect يكون مسجلاً ومطابقاً بدقة حتى ما يهرب authorization code لموقع مهاجم. معامل `state` عشوائي ومربوط بطلب المتصفح يساعد على كشف تزوير الطلبات وربط الرد بالجلسة الصحيحة؛ وPKCE يحمي الرمز من الاعتراض/الاستبدال خصوصاً للعملاء العامة. هاي دفاعات مختلفة ومتكاملة، وما بتصحح إعداداً سيئاً تلقائياً.

Access token بنوع Bearer يعني حامله يستطيع تقديمه؛ لذلك ما ينحط بعنوان URL أو سجل غير محمي، ويُفضّل أن يكون قصير الصلاحية ومحدود النطاق وقابلاً للإلغاء. Refresh token أطول عمراً، فيحتاج حماية أشد وتدويراً/إبطالاً وفق التصميم. TLS يحمي القناة أثناء النقل، لكنه ما يحمي رمزاً مسروقاً من جهاز أو سجل.

إذا التطبيق بده يعرف المستخدم، لا تستنتج الهوية من access token أو من مجرد امتلاكه. استخدم [OpenID Connect](topic:openid-connect-jwt) المصمم لطبقة المصادقة. والتصميم الجيد يجمع التفويض المحدود مع [أقل صلاحية](topic:access-control-models)، ومراقبة ومراجعة الصلاحيات.

_مثال المصدر:_ تطبيق طباعة صور يحتاج قراءة الصور لا حذفها. النطاق الضيق يقلل أثر سرقة الرمز أو إساءة استخدام التطبيق.

**مصطلحات English → Türkçe:** `delegated authorization` (Yetki devri), `client` (İstemci), `resource owner` (Kaynak sahibi), `access token` (Erişim belirteci), `scope` (Kapsam), `Proof Key for Code Exchange` (Yetkilendirme kodu için kanıt anahtarı), `state parameter` (Durum parametresi).
