## المفتاح يحتاج إدارة طوال عمره

كل الخوارزميات اللي تعلمناها تعتمد بالنهاية على سر يبقى سرياً. إدارة المفاتيح (key management؛ anahtar yönetimi) بتغطي دورة حياته: توليد بمولد عشوائي آمن CSPRNG، تخزين، توزيع للمخولين، استخدام، تدوير (rotation) ثم إتلاف آمن. وضع مفتاح بنص واضح في ملف إعداد أو مستودع Git خطير؛ تدويره يحد مدة الاستفادة إذا تسرب. الإتلاف يمنع مفتاحاً قديماً من فك بيانات لاحقاً. حذف السر المؤقت بعد جلسة ECDHE تطبيق بروتوكولي للمبدأ.

## خفض الثقة من البرمجيات للعتاد

وحدة أمن عتادية HSM (Hardware Security Module؛ donanım güvenlik modülü) تولد وتحفظ مفاتيح وتنفذ عمليات مثل التوقيع داخلياً؛ المفترض أن المفتاح لا يخرج كنص واضح. اختراق الخادم قد يسمح للمهاجم بطلب عملية من الوحدة إن كانت صلاحياتها مفتوحة، لكنه لا يعني تلقائياً إمكانية نسخ المفتاح. TPM وSecure Enclave ومخازن المفاتيح المدعومة عتادياً نسخ موجهة لأجهزة المستخدم.

## الجذر مسؤولية مشتركة

مفتاح Root CA بالغ الحساسية، لأنه يدعم الثقة في شهادات كثيرة. لذلك يخزن دون اتصال داخل HSM، واستخدامه يتم بمراسم موثقة بحضور شهود وسجلات. مبدأ المعرفة المجزأة (split knowledge) أو M-of-N يتطلب حضور عدد محدد من عدة مسؤولين/بطاقات لتفعيل العملية؛ لا يستطيع فرد واحد التصرف منفرداً. الفكرة ليست الثقة بشخص مثالي، بل تصميم إجراء قابل للتدقيق وتقاسم الصلاحيات.

## مصطلحات إنجليزية ومقابلاتها التركية

| المصطلح الإنجليزي              | المقابل التركي          |
| ------------------------------ | ----------------------- |
| Key management                 | Anahtar yönetimi        |
| Key rotation                   | Anahtar döndürme        |
| Hardware Security Module (HSM) | Donanım Güvenlik Modülü |
| Key ceremony                   | Anahtar töreni          |

**إضافة تعليمية:** HSM يقلل استخراج المفتاح لكنه لا يمنع إساءة استخدام وظيفة التوقيع إذا اختُرقت صلاحيات التطبيق. لذلك يلزم ضبط الوصول ومراقبة العمليات وخطة تدوير واستعادة.
